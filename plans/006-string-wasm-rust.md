# STRING — WASM + Rust Compute Kernel

**Vision**: Rewrite String's rendering pipeline in **Rust compiled to WASM**.
The 3D manifold visualization becomes a thin WebGL canvas that receives vertex
buffers generated by a WASM compute kernel running number-crunching algorithms
that would be slow in JavaScript. This is the "I can compile native code to the
browser" app.

**Current State**: 2819-line monolith HTML/JS. Three.js r160 via CDN.
SSAO + UnrealBloom postprocessing stack. 4D manifold visualization with
rendering technique toggles (wireframe, surface, particle). Controls for
manifold parameters.

## Key Upgrades

### 1. Rust → WASM Compute Kernel
- All manifold geometry generation moves to Rust.
- JavaScript calls `generate_manifold(params) -> Vec<f32>` once per frame
  (or once per parameter change).
- WASM returns a flat buffer of vertex positions, normals, colors, and indices.
- JS uploads the buffer to WebGL — no per-vertex JS processing.
- Parameters: shape, dimension, curvature, resolution, time.

### 2. Drop Three.js — Use Raw WebGL2
- Three.js post-processing (5+ passes) costs ~8ms per frame on the CPU
  just for JS overhead.
- Replace with a single custom shader that does bloom + tonemapping.
- The manifold is the star — post-processing should enhance it, not announce
  itself.

### 3. 4D Camera with Full Rotation
- Current: likely a standard 3D orbit camera controlling projection.
- New: implement a 4D camera that can rotate through the 4th dimension.
  User controls: 3D orbit (mouse drag) + W4 rotation (scroll / key).
- The WASM kernel receives the full 4D view transform and projects to 3D
  vertices at compute time.
- Result: the manifold warps as the user "rotates" the 4D view.

### 4. Geodesic Path Tracing
- Compute geodesic paths on the manifold in WASM.
- User clicks two points on the surface → WASM runs RK4 integration along
  the manifold to find the shortest path.
- Render the path as a glowing tube on the surface.
- Display path length in "manifold units."

### 5. Topology Computation
- Each manifold preset computes its Betti numbers (b0, b1, b2) in WASM
  via a simplicial homology computation on the tessellated mesh.
- Display in the UI: "Topology: Torus (b₀=1, b₁=2, b₂=1)".
- When user tweaks parameters, the topology is recomputed — if the manifold
  changes type (e.g., sphere → torus), the UI announces it.

### 6. Manifold Gallery
- 6-8 presets with curated color schemes and default camera positions:
  Sphere S², Torus T², Klein Bottle, Projective Plane RP², Calabi-Yau,
  K3 Surface, Hyperbolic Plane H², Figure-8 Knot Complement.
- Each preset sets the manifold equation, color map, and camera in WASM.
- User edits any parameter and can save as a custom preset (localStorage).

## Dependencies
- **Add**: `wasm-pack`, `rustc`, `wasm-bindgen`, `wee_alloc` (for size control)
- **Remove**: All Three.js CDN scripts (build raw WebGL2), postprocessing CDN
  scripts

## Challenges
- Rust WASM compilation adds a build step. Must integrate with Vite via
  `vite-plugin-wasm` and `vite-plugin-top-level-await`.
- WASM binary size must be <200KB gzipped. Use `wee_alloc`, strip debug
  symbols, and wasm-opt aggressively.
- 4D to 3D projection needs to handle degenerate cases (when the 4D view
  aligns the manifold so it appears 2D or 1D). The camera should have
  constraints to prevent this.
- Betti number computation on a 50K-triangle mesh should be fast enough in
  Rust but may need simplification if it takes >100ms.

## Verification
- Load app: bare HTML loads, WASM module initializes in <500ms
- Default torus renders at 60fps with bloom
- Rotating the 4D camera smoothly morphs the manifold
- Click two points → geodesic path drawn in <100ms
- Topology display shows correct Betti numbers for each preset
- Switch between all 8 presets — each renders correctly with its color scheme
- Build 160KB gzipped (WASM + JS + HTML)
